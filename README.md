## Redaction & Reproducibility statement

- All company names, target organizations, personnel, emails, phone numbers and macro financial
  figures across every preset, fixture, contract, report, export and log are strictly replaced with
  the canonical tokens `[REDACTED_ENTITY]` and `[REDACTED_AMOUNT]`.
- All IP infrastructure uses RFC 5737 documentation ranges (`192.0.2.0/24`, `198.51.100.0/24`,
  `203.0.113.0/24`) plus loopback/private space; the only exceptions are three documented
  boundary-probe literals inside `open-creation` self-test code, required to prove that containment
  math *rejects* addresses just outside a TEST-NET block (see `open-creation/README.md` §9).
- Each track ships its own automated redaction scan as part of its verification suite
  (`smb` `CHK-15`, `video-creation` `CHK-10`, `open-creation` `CHK-10`).
- **Zero-dependency, offline-first:** both web apps are true single-file builds (no CDN scripts,
  fonts or stylesheets; no build step). All three verification scripts are pure Python standard
  library (Python 3.8+), contain no randomness, and rewrite their `verification/` outputs
  deterministically — identical inputs always produce identical logs.
- Each track's verification log (`verification/run_log.txt`) is regenerated by the command shown in
  the table; a fresh, certified run is expected to end with `… CHECKS PASSED` (15/15 and 10/10
  respectively) before publishing.
